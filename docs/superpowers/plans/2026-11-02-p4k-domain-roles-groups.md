# P4k domain 4: role and group entities, the capability rules cleaned in place, pages/roles and pages/groups

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** what other slices read of a role or a group lives in `entities/role` and `entities/group`, the capability rules (default-block, ceiling, last-administrator, role owner) each have one owner, the layer-order gap is closed by a rule, and `features/roles`, `features/groups` become `pages/roles`, `pages/groups`, with no behaviour changed.

## Rulings

- **Entity `role`** = types, address (`rolesHref`, `roleHref`, `newRoleHref`, `rolesTrail`), `RolePicker` + `useRolePicker`, `RoleOwner`, `MappedRoles` + `mappedRoles.ts` (with `assignedRoles` moved from `clients/services/account.ts`, so no service needs a value from the entity index: `account.ts` keeps `AssignedRole` as a type), `rolesGoneReach`. Role CRUD, composites, copy, blocks, removal stay in the page. **Entity `group`** = types, address (`groupsHref`, `groupHref`, `groupsTrail`, `newGroupHref`), `GroupPicker` + `useGroupPicker`. Two consumers each beyond the slice (audit; pages/subjects, clients, scopes). **No `entities/capability`** (evidence above). Alternative rejected for `role`: a services-only index added to the `area`/`administrator` exception, because the pickers and `RoleOwner` are views.
- **The `'Roles'` and `'Groups'` labels in the entity addresses are literals** (an entity may not import `entities/area`); a page test asserts they equal `areaAt(...).label` (precedent: `'Subjects'`).
- **Domain types keep the wire's field names.** `Role`, `Group`, `GroupRecord` are declared in `entities/<x>/types` (structural copies the adapters return after the schema parse), so the 35 slice files stop importing contracts, but `admin_reach`, `client_key` and the rest are not renamed: five shared files, two entities and eleven unmigrated files read them. A camelCase pass is placed at the close sweep after domain 5. `EffectiveRoleAssignment`, `RoleProvenance`, `HeldAdminCapability`, `ListRoleCompositesResponse` and `SetGroupRolesResponse` stay contract types read by shared capability services (shared may not import an entity); placed to the close's contracts-only-in-adapter sweep.
- **No new feature.** The pickers are entity views (precedent `useSubjectPicker`); the "ceiling guard" has no view or journey, only five `ceilingCaller` call sites in hooks over shared rules; the held-capability editor is `features/subject-capabilities`. The one candidate, a "map roles onto X" editor, is borrowed by groups and scopes only (`RolesTab` 99 and 76 lines, `useGroupRoles` 140 vs `useScopeRoles` 95, they differ by loss confirmation and defaulting): placed to domain 5, when scopes migrates and there are two consumers.
- **Gallery.** `console-gallery-shows-only-view` admits only `shared/ui` and `shared/services`; the specimens for `RolePicker`, `GroupPicker`, `MappedRoles`, `RoleOwner` (`gallery/Gallery.tsx` 470, 476, 886, 1147, 1265) are domain views and leave with them; each keeps its own axe test. `ROLES` in `gallery/samples.ts` goes if unused.
- **Order.** The `git mv` comes after the entities, not first: this domain extracts no feature, and moving first would leave `clients` and `audit` (waiting slices) importing `pages/roles|groups`, which Task 0 forbids. The six sideways entries die at the move.
