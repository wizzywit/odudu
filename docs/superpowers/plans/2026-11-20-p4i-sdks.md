# P4i SDKs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the official sign-in SDKs, the generated admin and "me" clients (TypeScript and Python), a standalone `odudu mcp` package, nine CI-run examples and an SDKs docs section.

**Architecture:** TypeScript SDKs live in `sdks/*` (Apache-2.0, own versions, no `@odudu/*` server imports) over `oauth4webapi` and `jose`. Both OpenAPI documents are generated from route tables and committed; clients are generated from them and regenerated in CI. The BFF is `Request`/`Response` handlers that Next, Fastify and Express adapt. The stdio MCP code moves out of `@odudu/mcp` into `sdks/mcp-stdio`.

**Tech Stack:** TypeScript, pnpm workspace, vitest, Fastify (admin and "me" routes), `oauth4webapi`, `jose`, `openapi-typescript` + `openapi-fetch`, Python 3.10+ with `httpx`, Docusaurus.

**Spec:** `docs/superpowers/specs/2026-11-20-p4i-sdks-design.md` (approved by the owner 2026-11-20). Read it first; this plan only fixes what the spec leaves to the planner.

## Global Constraints

- Public names (npm scope chosen by the owner 2026-11-20, because `@odudu` is held by another npm user): npm `@odudu-io/oidc`, `@odudu-io/react`, `@odudu-io/bff`, `@odudu-io/next`, `@odudu-io/node`, `@odudu-io/admin-client`, `@odudu-io/me-client`, `@odudu-io/mcp-stdio`; PyPI `odudu`. Versions start `0.1.0`; tag `<name>-vX.Y.Z`.
- SDKs are Apache-2.0 under `sdks/*`; `sdks/*` imports no `@odudu/*` workspace package except another SDK. The server's `odudu mcp` imports `@odudu-io/mcp-stdio`, never the reverse.
- No `any`, no `void` statement, no inline `eslint-disable`, `complexity: 8` on use cases, no comment block over 8 lines, no process references in comments (CLAUDE.md).
- No tool-attribution trailer in any commit or PR body. Commit body at most 8 lines, subject at most 72 characters. No `git stash`.
- Heavy jobs (docker, e2e, Testcontainers int tests, the stack): `/Users/wep/WebstormProjects/odudu/.superpowers/sdd/tools/heavy-slot -- <cmd>` (pool `e2e`; `-p int -n 2` for int tests).
- Every claim about third-party behaviour carries `verified: <command>` once run, else `assumption:` with the spike that settles it. Every claim about this repository carries the grep beside it.
- ADR 0041: each path states its volume. JWKS cache bounded; BFF default store bounded; list helpers bounded; "me" document built once at boot; discovery cache bounded per issuer.
- Runtimes: ESM only, Node 24, React 19, Fastify 5 and Express 5 optional peers. `minimumReleaseAge: 1440` applies to every SDK dependency (`pnpm-workspace.yaml`).
- Every increment ends with a push, CI green on PR 235 and review threads answered; an increment merges into `feat/p4i-sdks`; the merge into `main` needs the owner's yes.

## Review Focus

1. A refresh token used twice concurrently by one app: exactly one `POST /token` is made (Odudu's reuse detection would end the family). Pinned in Task 10.
2. A callback with a missing, repeated or mismatched `state`, or no `iss`: refused, and nothing is exchanged. Task 9.
3. A token that is an ID token, names only the me audience, or has `typ` other than `at+jwt`, sent to an API: `401`/`403` in both `@odudu-io/node` and Python, same verdict from the shared fixtures. Tasks 12 and 21.
4. A cross-site `POST` to a BFF route (no custom header or wrong `Origin`) with a valid session cookie: refused, no refresh, no proxy call. Task 14.
5. A BFF proxy request to a host or path outside the allowlist, or an upstream redirect: refused, never followed, cookie never forwarded. Task 15.
