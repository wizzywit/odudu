## Rulings

- **Entity `subject`** = what 2+ slices read or write of a subject: types, address (`subjectsHref`, `newSubjectHref`, `subjectHref`, `subjectsTrail`, `subjectTabHref` with the tab ids), `subjectName`, `usernameOrId`, the subject's reach (`reach.ts`, pure over shared), role-splitting rules, the list/create/password/roles calls and the whole access repository. Page-only journeys (credentials, mail, sessions, profile, record) stay in the page.
- **Entity `administrator`** = provisioning rules only (calls, request needs, `administratorNeeds`, `holdingsProblem`, role finders). Five page and feature services call it for values, so its index is services- and types-only and is added by name to the `entities/area` exception in `console-service-entity-index-type-only`; a test in the same commit asserts such an index exports nothing from `use-cases`, `ui` or `repository`. Cost if wrong: one regex edit. Alternative rejected: five services take the rules as arguments.
- **No `membership` entity**: `memberships.ts` has one importer (`useSubjectGroups`, `grep -rln "services/memberships'"`), and `useMemberships` stays with the access repository.
- **`administrator` imports no entity**, so the orchestration that calls subject adapters (`grantHoldings`, `refusedAt`, `defect`, `Refused`, `readAdminClients`, `readClientRoles`) goes to `features/grant-administrator` (consumers: `pages/tenants/repository/useCreation`, the system-admins page). `useOwnRoles` needs `usePrincipal` from `entities/session`, so it is `features/own-roles` (an entity may not import one).
- **Capability vocabulary and the refusal family stay in shared until domain 4.** A new shared file would add an inventory entry, which the ratchet refuses, so the constants and the tenant-reach rule move into the existing `capabilities/holdings.ts` (`TENANT_ADMIN`, `MANAGE_TENANTS`, `administratorCapability`, `tenantAdminCarries`, new `carriesTenantReach`); `subjectRefusal`, `accessRefusal`, `changeFailureText` append to `capabilities/refusal.ts`; `Confirmation`, `removalConfirmation`, `onlyHolderText` to `capabilities/loss.ts`; `offersWrites` to `shared/services/access.ts`. Evidence: every consumer (five services, four page hooks, the capability editor) can import shared and only shared. Domain 4 merges the two last-administrator phrasings.
- **`SubjectCapabilities`/`CapabilityHolders`/`CapabilitySection` become `features/subject-capabilities`** with `useCapabilities`, `useCapabilityHolders`, `useHolders`; `RolesTab` (page) imports its index. `BeyondNote` stays in the page (one importer, `SubjectRecordPage`).
- **Contract mapping scope**: `Subject` and `ListedSubject` become camelCase domain types (`createdAt`; 11 snake_case reads in these slices, `grep -rn "\.created_at\|\.email_verified" features/subjects features/system-admins`); `Credential`, `Lockout`, session, consent and grant rows are mapped in the page adapters; profile claims keep their OIDC claim names; `EffectiveRoleAssignment` and `HeldAdminCapability` stay contract types until the capabilities domain.
