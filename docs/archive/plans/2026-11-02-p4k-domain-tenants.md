## Global constraints

- Behaviour never changes. Moves use `git mv`; importers are repointed by script; imports carry no `.ts`/`.tsx`; tests move with their code.
- Layer order `app > pages > widgets > features > entities > shared`. Entities and shared never import widgets, pages, features or app; an entity imports no entity; shared imports no entity. A not-yet-migrated `features/<area>` is a page in waiting and may import widgets and entities.
- An index exports only `ui|use-cases|services` (type-only exports are free); a repository function reaches another slice through a thin use-case re-export (precedent `entities/session/use-cases/rememberedTenant.ts`); an adapter is never exported. A service imports an entity index for types only (rule `console-service-entity-index-type-only`; `entities/area` excepted).
- A migrated view imports no service or repository: route through a use-case. A service file is named for a concept, stays under 300 lines.
- `AdminCapability`, `Authority`, `SYSTEM_TENANT` stay in `shared/services/principal.ts` until the capabilities domain.
- CLAUDE.md comment rules, no `any`, no `void` statements, commit subject at most 72 characters, body at most 8 lines, no tool-attribution trailer.
- Each task ends with `pnpm format:check && pnpm lint && pnpm typecheck && pnpm boundaries && pnpm test:unit`, plus `pnpm --filter @odudu/docs test` when a console path moves. Inventories (`tests/lint/architecture/inventory.ts`, `inventory.baseline.json`) shrink in the commit that resolves them.

## Rulings

- **Entity `tenant` = what 2+ slices read of a tenant**: the settings record, the enabled/disable rules and the offered locales. The tenant record, list and CRUD stay page-local (one consumer).
- **Entity `creation-draft`** (a feature may not hold it: a page service imports an entity index for types but may not import a feature index). It holds the draft's types, state rules, storage and step address; the begin action sits above it.
- **`SystemGate` goes to `widgets/shell`** beside `AreaGate`: a feature may not import `useArea`, and a widget may not import the sibling widget. The hook `useTenantsArea` moves with it.
- **`branding/services/languages.ts` cannot value-import the entity** (service to entity index is type-only): `languageSettingsOf(settings, supported)` takes the offered locales as an argument; `useLanguages` and `LanguagesTab` pass `offeredLocales(settings)` from the entity index.
- `carriesTenantReach` (audit 2.8) is in `subjects/holdings.ts`, not here (`grep -rn "holding ===" features/tenants` is empty): it stays placed with domain 3. The `lacking(...).length` variants are not in this domain (all eight `lacking(` calls here use the returned list).
