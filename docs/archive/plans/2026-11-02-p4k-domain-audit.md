# P4k domain 6: the audit-event entity, a record-activity feature, pages/audit

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** the audit rows every Activity tab, the overview strip and the Audit trail draw live in `entities/audit-event`; the Activity tab of a record is `features/record-activity`; `filters.ts` and the other mixed service files are split by concept, each rule has one owner, and `features/audit` becomes `pages/audit`, with no behaviour changed.

**Spec:** `docs/superpowers/specs/2026-11-02-p4k-frontend-architecture-design.md`. Parent: `2026-11-02-p4k-frontend-architecture.md`, tasks D-A to D-G. Model: `2026-11-02-p4k-domain-clients-scopes.md`.

## Global constraints

Those of the domain-5 plan apply unchanged: layer order `app > pages > widgets > features > entities > shared`; a feature imports no page, no other feature and, unless a waiting slice, no widget; entities and shared import no upper layer, an entity imports no entity, shared imports no entity; an index exports only `ui|use-cases|services`, type-only free; a repository or adapter function other slices call goes through a thin use-case re-export (precedent `entities/subject/use-cases/subjectCalls.ts` over `repository/subjectCalls.ts`); adapters never in an index; use-cases reach adapters only through the repository segment; a service imports an entity index for types only (`entities/area`, `entities/administrator` excepted) and any slice's `types/`; migrated views import no service or repository, so text and rules reach them through use-cases that take them from view models, not no-op bags; files named for concepts, under 300 lines; a new file under `shared/` adds an inventory entry the ratchet refuses, so none is added. Every task ends with `pnpm format:check && pnpm lint && pnpm typecheck && pnpm boundaries && pnpm test:unit` plus `pnpm --filter @odudu/docs test`. Inventories and the baseline shrink in the commit that resolves them. Dispatches quote the comment rules and the heavy-slot lock. Starts after domain 5 is merged: audit imports `clientHref`/`scopeHref` from `#/entities/client|scope`, and `ClientRecordPage`/`ScopeRecordPage` are in `pages/` (Task 6 edits them).

## Rulings

- **Entity `audit-event`** = `AuditEvent` type (wire field names kept), `readAuditPage` (adapter `auditPage.ts` with a test over the transcript, `repository/auditCalls.ts`, `use-cases/auditCalls.ts`), and the row views `AuditTable` (+ `auditColumns`), `AuditDetail`, `AuditActor` with the rules they read: actor origin, request correlation, detail entries. Its views get their rules through use-cases (`useAuditTable`, `useAuditDetail`, `auditActorOf`), since the entity is migrated. Alternatives rejected: leaving the views in `shared/ui` (the ratchet counts them as domain), a `features/audit-table` (it is what an audit event looks like, not a journey; three slices read it, one is overview).
- **`exportAuditEvents` leaves `shared/adapter/audit.ts` for `pages/audit/adapter/auditExport.ts`**; the entity adapter holds only the read. The record-activity feature and overview call `readAuditPage` through the entity.
- **Feature `record-activity`** = `RecordActivity`, `ActivityTab`, `useRecordActivity` (merging `useActivity`, 23 lines, and its pass-through, 12 lines; the one test is moved) with the Activity wording. Five page consumers, none of which import each other; it imports only `entities/audit-event` and shared lists. The `'client' | 'group' | …` resource union is a type of the feature, and `noun` stays the audit log's resource type.
- **Order: entity (Task 5), feature (Task 6), then `git mv` (Task 7)**, as domains 4 and 5. The move cannot lead: it leaves `shared/ui/Audit*` and the adapter inventoried, and the move step is where the audit views are routed through use-cases. Neither `features/overview` (waiting) nor the record pages reach `pages/audit`, so the order is for the ratchet, not a breach.
- **Pages import entities and features only through indexes**; `AuditPage` takes `CORRELATION_NOTE`, `EXPORT_NOTE` and the empty and stale texts from the `useAuditPage` view model, not from services.
- **Placed out, by name.** The `NEEDS` capability table and the area paths in `overview/services/reads.ts:80`, `tokensHref`, `sessionsHref` (audit-B 15-17): the domain that owns each of those slices, with `AREA_PAGES` left to say which audit resource types have no record page. The overview's second strip column set is placed here (Task 3), not there, because it is a copy of this entity's rule.
