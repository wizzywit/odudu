# P4k domain 7: the branding editor feature, pages/branding, one owner per rule

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** the theme, pages and publication editors that the Branding area and a client's Branding tab both draw are `features/branding-editor`; the area's own tabs (mail, languages, message overrides) are `pages/branding`; the 26 service files are split by concept, the five scheme spellings, the "show N, N more" pattern and the limit reading each have one owner, and the 18 views take their text from use-cases, with no behaviour changed.

**Spec:** `docs/superpowers/specs/2026-11-02-p4k-frontend-architecture-design.md`. Parent: `2026-11-02-p4k-frontend-architecture.md`, tasks D-A to D-G. Model: `2026-11-02-p4k-domain-clients-scopes.md`; the audit plan (domain 6) is assumed landed.

## Global constraints

Those of the domain-5 plan apply unchanged: layer order `app > pages > widgets > features > entities > shared`; a feature imports no page, no other feature and no widget (it is not waiting once migrated); a page may import features, widgets and entities (never another page: `no-sideways-slice` counts `pages`); entities and shared import no upper layer, an entity imports no entity, shared imports no entity; an index exports only `ui|use-cases|services`, type-only free; a repository or adapter function another slice calls goes through a thin use-case re-export (precedent `entities/subject/use-cases/subjectCalls.ts`); adapters never in an index; use-cases reach adapters only through the repository segment; a service imports an entity index for types only and any slice's `types/`, so a rule that needs an entity value takes it as an argument; migrated views import no service or repository, and **a use-case phrases nothing and decides nothing**: sentences joined from constants and counts are pure service functions (`spaced()` is in `shared/services/format.ts:76`), no no-op bags, and a return bag over about 12 fields is grouped per section; files named for concepts, under 300 lines; a new file under `shared/` adds an inventory entry the ratchet refuses, so shared code grows only inside existing files. Every task ends with `pnpm format:check && pnpm lint && pnpm typecheck && pnpm boundaries && pnpm test:unit` plus `pnpm --filter @odudu/docs test`. Dispatches quote the comment rules and the heavy-slot lock. **Behaviour never changes:** where two copies disagree, the owner gets a named option, the disagreement is listed under "Variants kept", and a test pins each variant before the copy is deleted.

## Rulings

- **No entity.** An entity is a noun two or more slices read; the only reader outside branding is `pages/clients`, and it reads editors, not a record (`ThemeView` has no consumer outside the slice, Evidence). The theme record stays types of the feature. Alternative rejected: `entities/theme` holding `ThemeScope` and the record (one consumer, and it would sit beside the console's unrelated light/dark `shared/services/theme.ts`).
- **`features/branding-editor`** = what both the Branding page and a client's Branding tab draw: `ScopePanels` (`ThemePanel`, `PagesPanel`), `ThemeTab`, `PagesTab`, `ColoursSection`, `ImagesSection`, `StylesheetSection`, `PublicationBar` and its panels and revert conflict, `PreviewPane`, `PreviewShell`, `PreviewFrame`, `OptionPicker`, `MessageKeyField`, `SlotThumbnail`, the colour, image, template, stylesheet, publication, versions and preview rules, the repository of the theme record and writes, and `useScopeBranding`, `useScopeEdits`, `useTenantEdits`, `useScopeTabReads`. Its index exports those two panels, `PublicationBar`, `PreviewShell` (the mail tab frames its preview in it), `MessageKeyField` and `useMessageKeys` (the languages tab picks keys from the catalogue), the three hooks, `clientScope`, `ThemeScope`, `selectScopedTab`, `showsPreview`, `SCOPED_TABS` and the two labels. The feature imports no entity but `session` and `tenant`, no widget and no page. Name `branding-editor`, not `branding`, so it cannot be mistaken for the area.
- **`pages/branding`** = `BrandingPage`, `Workspace`, `MailTab`, `MailClientChoice`, `LanguagesTab`, `useBrandingPage`, `useMailTab`, `useLanguages`, the mail and override adapters and repository, the languages, overrides, override-conflict and mail rules. It composes the feature through its index; `BrandingPage` already imports `AreaGate` from `widgets/shell`, legal for a page, so `branding` leaves the `console-features-import-no-widget` waiting list (`waiting.test.ts` fails otherwise).
- **Order: split and move in one commit (Task 10), then migrate views (Task 11).** The two usual orders each need a commit the ratchet refuses: moving first makes `pages/clients` import `pages/branding` (sideways), extracting first makes `features/branding` import `features/branding-editor` (sideways), and domain 5 paid for that with a temporary baseline raise. One commit that `git mv`s the editor files into the feature and the remainder into `pages/branding`, repointing `pages/clients` and `router.tsx` by script, never leaves either state. It is mechanical (no symbol changes) and comes after the service split so that its diff holds no rule edits.
- **Scheme owner.** `services/colourScheme.ts` (the `Scheme` concept leaves `palette.ts`: `Scheme`, `SCHEMES`, `schemeOf`) owns the labels with named forms: `SCHEME_LABELS` ("Light"), `schemeOptions` (the id/label list `SCHEME_OPTIONS` was), `schemeColoursTitle(scheme)` ("Light colours", for `mail.ts` and `fields.ts`), `schemeColoursName(scheme)` (lower case, for `sources.ts`; derived, same text), `SCHEME_PICKER_LABEL` ("Colour scheme", for preview and mail). The `ColoursSection` strings `customLabel(...toLowerCase())` and `` `${label} ${palette label}` `` read the same owner. Variants kept: none differ in text; the three capitalisations are options, pinned by a test that lists all five forms for both schemes.
- **One `shown` and one `limitReading`** (placed here by domains 5 and 8's audit rows). `shown(items, limit)` returns `{ items, rest }` and `moreCount` text through `counted`; they join `shared/services/format.ts`, beside `counted` and `byteSizeReading`, not a new file. `limitReading(used, limit, noun, unit)` is the owner of both `listCount` ("N of M noun" / "N over the limit of M noun") and `byteSizeReading` ("N of M bytes." / "N bytes over the limit of M."): the two disagree on the trailing full stop and on grouping (`groupedNumber` for bytes, plain for counts), so the owner takes `{ grouped, stop }` as a named option and both existing callers keep their text. The limits themselves (50, 50, 20, 20) are not merged: `PROBLEMS_SHOWN` 20 and the 50s are different decisions. `email` follows in domain 8.
- **Placed out, by name.** `NAME`-style fixed-wording constants and capability sentences stay per slice (domain 4/5 rulings). The contracts-only-in-adapter sweep and camelCase of wire fields: the closing sweep, as in domains 4 and 5.
