# RFC 7591 — OAuth 2.0 Dynamic Client Registration Protocol

**Status in Odudu:** only §2.2 (Human-Readable Client Metadata) is tabled
here, because it is the one clause of the registration protocol that gained
behaviour of its own: `client_name#<language>` members, kept in
`clients.name_i18n`. Registration itself, its policies and its metadata
validation are covered by the `ODUDU-CLIENT-REGISTRATION-*` tests in
`packages/protocol-oidc/tests/client-registration.int.test.ts`, which name
Odudu's own properties rather than clauses of this RFC.

## Reading notes

### Which language-tagged members are read

§2.2 lets every human-readable member (`client_name`, `client_uri`,
`logo_uri`, `policy_uri`, `tos_uri`) carry a BCP47 tag after a `#`. Odudu
reads only `client_name#<tag>`, the one a page shows. The others are
ignored and never echoed (`ODUDU-CLIENT-REGISTRATION-LANGUAGE-03`).

A tag is kept only when the tenant offers that language
(`tenants.supported_locales`); an unoffered tag is dropped and not echoed
(`ODUDU-CLIENT-REGISTRATION-LANGUAGE-01`). A tag that is not a language tag,
one spelled twice in different case, or a value that fails the checks
`client_name` has is refused with `invalid_client_metadata`
(`ODUDU-CLIENT-REGISTRATION-LANGUAGE-02`). Tags are matched without regard
to case and echoed in their canonical spelling, as §2.2 recommends
(`RFC7591-2.2-01`).
