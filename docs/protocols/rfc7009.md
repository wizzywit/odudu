# RFC 7009 — OAuth 2.0 Token Revocation

**Status in Odudu:** in scope for P3b in full, per the design spec's §8.3:
`/revoke` against the grant the token names. No `/revoke` endpoint exists
in this repository yet — this table is written before the endpoint that
resolves its rows, alongside `rfc7662.md` and `rfc8707.md`. §1
(Introduction) and §1.1 (Requirements Language) are non-normative and out
of scope; §3 (Implementation Note) is design background on the trade-offs
between self-contained and handle-style access tokens, with no capitalized
RFC 2119 keyword in it, and is not rowed; §4 (IANA Considerations)
registers the error code and the token-type-hint registry themselves, not
an entry the server would add to either, and is not rowed; §6
(Acknowledgements) and §7 (References) are never rowed.

## Reading notes

### TLS on the revocation endpoint

§2 carries two MUSTs that the revocation endpoint's URL is HTTPS and that
the authorization server uses TLS in a version compliant with RFC 6749
§1.6. Odudu terminates no TLS — `docs/protocols/rfc6749.md`'s reading note
"TLS: what a boot guard settles, and what it does not" is the standing
account of what `assertProductionTls` does and does not prove, and both
rows here are `accepted:` against it rather than newly argued. The
client-side MUST beside them, that the client itself verifies the URL is
HTTPS before using it, is `n/a`: Odudu is the authorization server serving
that URL, not the client validating it.

### The HTTP-fallback SHOULD, deferred rather than accepted

§2's SHOULD that a host reachable over HTTP also offers a revocation
service at the corresponding HTTP URI — while never publishing that URI as
_the_ revocation endpoint — reads at first like the same accepted-against-
the-proxy claim as the TLS rows above: Odudu serves plain HTTP behind a
TLS-terminating proxy uniformly, with no code path that distinguishes an
HTTP request from an HTTPS one. But the obligation here is not about the
wire protocol; it is a registration and advertisement policy — offer the
service at a second, unadvertised location — that only has an answer once
`/revoke` and its discovery metadata exist to have a policy about. Nothing
in this repository today has decided either way, so this row and its
companion (not publishing that URI as the endpoint) are `deferred: P3b`
rather than `accepted:`.
